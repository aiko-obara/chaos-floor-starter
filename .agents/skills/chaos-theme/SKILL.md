# カオスのテーマを制作する

このスキルはCHAOS FLOORリポジトリと一緒に使う。ルートはこのファイルから `../../..`。プロジェクトのAGENTSと現在のWikiを読み、既存の配置・ステージ・並行変更を確認する。

制作工程と採用基準の正本は[implementation-process.md](../../../.wiki/wiki/implementation-process.md)。最初に読み、対象テーマに関係する事例だけ追加で読む。加工レシピは [recipe-format.md](references/recipe-format.md)。個人のMacの絶対パスや外部スキルの設置場所へ依存しない。

## 結果として揃えるもの

テーマの同定根拠、画風参照、実際に使った生成プロンプトと原画、加工レシピとQC、採用したPNG/atlas、room JSON、実ブラウザの動作・停止・保存の確認をひとまとまりに残す。世界全体と番地内の一式、Musicを区別する。

## 判断を左右する基準

- 利用者のテーマから人物・衣装・作品版・代表物を同定し、画像と出典を確かめる。テーマ名を勝手にMusicへ読み替えない。曖昧さで外見が変わる場合だけ具体例で確認する。
- `recipes/style-baseline.json` の画像を実際に見て、役割を分けて生成の参照へ渡す。元作品の画像は外見の同定、共通スプライトは画風、layout guideは配置だけに使う。基準に写ったキャラクターや小物を別テーマへ混入させない。
- 素材原画は利用可能な画像生成ツールで作る。コード描画の仮素材を完成品として扱わない。生成環境が無い場合は準備済みと未生成を区別する。現在の作例はbuilt-in image_gen由来で、Webの自由生成APIが完成したとは扱わない。
- キャラクターにはテーマに合う読める具体的な行動を1系列、機構物には機構に合う動きを与える。呼吸・瞬きだけで「食べる」「欠伸する」を満たしたとしない。
- 多コマの身体は複数行のグリッドにし、固定の向き・縮尺・足元と中央60〜70%の余白を指示。9コマなら3×3、4コマなら2×2が既存例。主役、特徴物、小物パックを分け、横長の車両・建物を小物用正方形枠へ無理に詰めない。
- `scripts/process_sprite_recipe.py` で加工と追加補正をレシピへ記録。端接触、切れ、空フレーム、不要な残色、接地と動作の読みやすさを確認。生成不足をQC閾値の緩和で解決しない。色除去の追加パスは必要な場合だけ使い、衣装の必要色を消していないか見る。
- 床・壁・通路・大型設備は共通ステージ、人物・テーマ小物はルームに属する。世界全体の材質や接続をテーマ追加だけで変えない。番地を跨ぐ深度と手前ガラスを実画面で確認する。
- 新素材の作成だけで配置・保存まで済んだとしない。既存worldを保存してから一式を配置し、再読込後のJSON、旧部屋・Music・stage seedを比較する。並行する本人の配置変更は巻き戻さない。

新テーマを依頼された範囲で制作・検証する。テンプレートの外部公開、GitHub新設、Xへの投稿、生成APIの実課金設定は制作依頼から推測しない。新しい出力の本人評価と機械QCは区別して引き継ぐ。
