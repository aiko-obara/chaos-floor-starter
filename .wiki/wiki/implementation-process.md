# 別テーマを同じ画風・品質で作る

入口は [.agents/skills/chaos-theme](../../.agents/skills/chaos-theme/SKILL.md)。[最初のテーマ制作](../../docs/CREATE_A_THEME.md)を使い、コードと同じGitで入力・結果・判断を管理します。

| 工程 | 次の人へ渡す記録 |
|---|---|
| 対象の同定 | 対象の版・衣装・外見、参照画像と出典。作り手の解釈と本人指定を区別 |
| 動作と構成 | 主役の始点→山場→終点、特徴物、小物。瞬きだけで具体的な行動を代用しない |
| 画風の一致 | recipes/style-baseline.jsonの実画像。identity/style/layoutの参照の役割を分ける |
| 原画の生成 | 実際のprompt、raw PNG、参照、生成ツール。取得できないモデル版・seedは不明と記す |
| 加工 | processorの版、recipe、追加色除去、QC、最終PNG/GIF、rawと出力のhash |
| 統合と保存 | sample/room JSON、一式を番地へ置くworld JSON、画像一式、追加前後の比較 |
| 確認と採用 | 端接触・空コマ・接地の機械確認と、実際の動き・輪郭・縮尺・重なり・保存の確認 |

画風は輪郭が明確なピクセル、2:1の等角投影、約30度の視点。consoleは材質、観測ロボは身体の輪郭と縮尺の作例です。別テーマへロボの外見を固定しません。3×3・384px・9コマは例であり、横長の物を小物用の正方形枠へ押し込まないでください。

ループごとにgrid・縮尺・接地・タイミングを記録します。色抜きの追加パスは必要な場合だけ使い、必要な衣装色を消していないか目視します。大きな構造はステージ、テーマの小物はルームとして扱います。共有の通路と手前ガラスを実画面で確認します。

画像生成には揺らぎがあるため、同じ品質は参照と採用条件で確認します。`npm run check:sprite-recipe` はデモ原画からの加工をRGBA画素で検証し、新しい原画の画質を自動保証するものではありません。採用済みの完成状態を渡す場合は、PNG・atlasとworld JSONを一緒に保存します。

新しい出力への本人評価、機械QC、ブラウザ操作、実機確認は別々に記録します。詳細は [recipeの形式](../../.agents/skills/chaos-theme/references/recipe-format.md) と [素材の来歴](../../docs/ASSETS.md) を参照してください。
